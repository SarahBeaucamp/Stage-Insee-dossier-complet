# Read me

Dans ce dépôt, il y a trois principaux dossiers :
- Prise_en_main,
- Dossier_complet_au_format_observable,
- Methodes_d_apprentissage_problématique_et_observable.
  
Dans le premier dossier « Prise_en_main », il y a dix sous-dossiers qui sont chacun nommés selon l’un des grands titres du dossier complet de l'INSEE. Dans ces sous-dossiers, se trouve pour de nombreuses tables du dossier complet le code en R qui permet de reproduire la table et le graphe, ainsi que le code pour avoir cette même représentation sous Observable. Ensuite, il y a également des sous-dossiers appelés « TOTAL » qui contiennent le code pour générer la page Observable de toute une catégorie entière du dossier complet.
Ce dossier « « Prise_en_main a été créé au début du stage et a permis une familiarisation avec Observable et le dossier complet. Le fait d’avoir le code en R et le code pour générer l'Observable du même graphique en parallèle aide grandement à la compréhension de la technologie pour une personne qui n’y est pas familière.
Le dossier « Dossier_complet_au_format_observable » contient tous les fichiers nécessaires à la reproductibilité du dashboard Observable, consultable en ligne via ce lien : https://sarahbeaucamp.github.io/Stage-Insee-dossier-complet/Dossier_complet_au_format_observable/. Dans ce dashboard, un premier menu déroulant en haut à gauche permet de naviguer entre plusieurs des grands thèmes du dossier complet. Le second menu déroulant sert à naviguer entre les sous-thèmes du grand thème sélectionné au préalable.
Dans ce même dossier, le code correspondant à chacun des grands thèmes est écrit dans un fichier .qmd. Lors du render de ce fichier, un fichier au format HTML est obtenu. Il suffit de cliquer sur ce fichier HTML afin de consulter le dashboard. Attention cependant, afin d’avoir le dashboard complet et de pouvoir naviguer entre tous les thèmes, il est nécessaire que les fichiers HTML de tous les thèmes soient créés et stockés dans le même dossier, sinon la navigation est impossible.
Dans ce dashboard, plusieurs représentations ont été testées : des histogrammes horizontaux et verticaux, des camemberts avec pourcentages intégrés, un treemap, des histogrammes empilés, des histogrammes avec pourcentages et dégradés de couleurs, des cartographies, une pyramide des âges, des tableaux et des graphiques.
De plus, certaines bases de données intermédiaires ont été créées afin de faciliter l’implémentation du dashboard et de réduire le temps de chargement. Ces tables étaient initialement stockées sur le S3 du Datalab SSP Cloud, mais elles sont maintenant stockées sur le dossier d'échange Didoc de l'INSEE.
Le dossier « Methodes_d_apprentissage_problématique_et_observable » contient des traitements statistiques plus poussés. Ceux-ci visent à comprendre quels facteurs (structure familiale, précarité, type d'emploi, taux de pauvreté) expliquent l'écart de taux d'activité entre les hommes et les femmes à l'échelle communale.
Pour cela, trois algorithmes d’apprentissage différents ont été réalisés sur la base de données 2022 du dossier complet : une régression Lasso, une Random Forest et un modèle XGBoost. Cela a eu deux objectifs principaux : explorer et exploiter le format Parquet plus en profondeur, et tenter de nouvelles représentations sous Observable. Les trois modèles ont été entraînés sur la base de données 2022, et ensuite les modélisations Observable sont rendues visibles avec les prédictions sur la base de données 2023.
Il y a ainsi cinq sous-dossiers dans le dossier « Methodes_d_apprentissage_problématique_et_observable ». Le premier est un dossier Base de données, avec les traitements réalisés sur les bases 2022 et 2023. En effet, afin de pouvoir lancer ces algorithmes, des réglages ont dû être faits, tels qu'un pivot pour mettre les bases au format ligne en Parquet, un filtre pour sélectionner les variables d’intérêt, la définition de la variable d’intérêt, le traitement hybride des valeurs manquantes, et l’uniformisation des noms de variables entre 2022 et 2023 qui ne sont pas forcément les mêmes.
Ensuite, il y a trois sous-dossiers qui sont respectivement GLM (qui contient le code pour la régression Lasso, l’évaluation de l’importance des coefficients et des performances), Random_Forest (qui contient le code pour la mise en place de la Random Forest, l’évaluation des performances et l’optimisation des hyperparamètres), et XGBoost (qui contient le code pour l’implémentation du modèle XGBoost et l’évaluation de ses performances). Enfin, il y a un sous-dossier Observables, avec en son sein cinq sous-dossiers qui contiennent chacun un dashboard différent présentant les résultats des modélisations.
Parmi eux, il y a les sous-dossiers Observable_lasso et Observable_lasso_spop. Tous deux suivent la régression Lasso, mais dans le second, les variables relatives à l’âge de la population ont été enlevées pour les traitements. En termes de prédiction, le modèle Lasso est de loin le moins performant, mais ce modèle permet la mise en place de curseurs interactifs et un recalcul en direct de la prédiction, ce qui est très intéressant d’un point de vue datavisualisation.
Dans la même logique, il y a les sous-dossiers Observable_xg et Observable_xg_spop, qui contiennent les résultats de la prédiction via le modèle XGBoost. Puis, il y a le sous-dossier Observable_rf qui contient les résultats et la visualisation des prédictions de la Random Forest.
Globalement, dans ces cinq sous-dossiers, il y a à chaque fois un fichier R de nettoyage et de mise au format de la base 2022, un pour la base 2023, un fichier R de génération des prédictions, un fichier R pour créer la table regroupant les valeurs réelles et les prédictions, ainsi que le fichier .qmd pour générer le dashboard. Dans ce dashboard, une première page montre via des blocs KPI le résultat réel et la prédiction, avec en dessous un graphe affichant les cinq variables influençant le plus la prédiction. Une seconde page affiche la cartographie au niveau France des prédictions et des valeurs réelles. Une troisième page propose une cartographie de ces prédictions au niveau départemental. Enfin, pour le modèle Lasso, un système de curseurs interactifs permet de recalculer en temps réel les prédictions.
Les avantages et inconvénients de chaque modèle sont bien distincts. Le modèle Random Forest est le plus performant en termes de prédiction, mais c’est également le modèle le plus long en termes de temps d’exécution, avec 18h nécessaires pour générer le fichier contenant les valeurs prédites et les cinq principales valeurs SHAP (qui permettent de mesurer l’importance des variables dans la prédiction). Le modèle Lasso est rapide à implémenter et permet la mise en place de curseurs de recalculs interactifs, mais il est peu performant en termes de prédictions. Enfin, le modèle XGBoost est le compromis entre les deux modèles précédents, avec un temps d’exécution raisonnable et des prédictions situées entre celles du Lasso et de la Random Forest.
Le choix de créer des modèles sans les variables d'âge de la population découle de la volonté de faire de ce dashboard un outil potentiellement utile en termes de politique publique. Ainsi, les variables d’importance sont uniquement des variables sur lesquelles un décideur public pourrait avoir une incidence, bien que cela réduise la performance des modèles.
Afin de mettre en place les dashboards de visualisation des résultats, de nombreuses tables intermédiaires ont dû être créées pour pallier les problèmes de temps de chargement. Lors de la réalisation initiale de ce projet, ces tables étaient stockées sur le S3 du Datalab SSP Cloud. Maintenant, celles-ci sont stockées sur le dossier d'échange Didoc de l'INSEE.
